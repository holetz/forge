## Problem

The local compose profile (spec 3, PR #19) works with its defaults. Its conclude review found a P2: dex's static config fixes the redirect URI and issuer. Overriding `OMNIGENT_PORT`, `OMNIGENT_OIDC_CLIENT_ID` or `DEX_PORT` in `.env` therefore breaks the OIDC login, with a redirect mismatch or an issuer mismatch. The overrides should flow into dex's config, through a rendered config or environment expansion. `scripts/smoke-local.sh` should prove one non-default port set.

Member of holetz/forge epic 1 (follow-up of S13).

## Proposal

Make the three overrides flow into dex. The issuer becomes `http://dex.localhost:${DEX_PORT:-5556}/dex` in both dex and Omnigent; dex listens on `DEX_PORT` inside its container and the published port maps `DEX_PORT:DEX_PORT`, so the Omnigent container reaches the same `host:port` the browser uses. The static client id is `OMNIGENT_OIDC_CLIENT_ID` and its redirect URI is `http://localhost:${OMNIGENT_PORT:-8000}/auth/callback`, the value Omnigent already receives. `scripts/smoke-local.sh` runs the whole stack on one non-default set of the three and still ends in a logged-in session.

## Out of Scope

- The live Unity Gateway check and any Databricks or paid call: the stub stays the only model endpoint.
- Changing the pinned images, the router, the stub, `verify_repo.sh` or `ci.yml`.
- Overrides of `ROUTER_PORT` and `STUB_PORT`: they are host-published ports only and already work.
- Moving the issuer off `dex.localhost`.

## Validation

- `DEX_PORT=15556 OMNIGENT_PORT=18000 OMNIGENT_OIDC_CLIENT_ID=omnigent-smoke docker compose --env-file .env.example config` shows the issuer `http://dex.localhost:15556/dex`, the redirect `http://localhost:18000/auth/callback` and the client id on the Omnigent service; before the change it shows the fixed issuer on 5556, so the check fails first.
- `bash scripts/smoke-local.sh` exits 0 with the non-default set: dex discovery reports the overridden issuer, the authorize redirect carries the overridden redirect URI and client id, and the scripted login ends with the dev user's session.
- `bash scripts/verify_repo.sh` exits 0 (`verify_repo: green`).
- Invariant: no paid or Databricks call; teardown with `down -v`; only images the run pulled are removed.

## Design

### Mapa de dependências

`compose.yaml` and `local/dex/config.yaml` are read only by `scripts/smoke-local.sh` and the README quickstart; `verify_repo.sh` runs `docker compose --env-file .env.example config -q` over the compose and must stay valid with defaults. Nothing else references the dex port, issuer or client id. (2026-10-25)

### Rendering

Dex's own `expandEnv` is rejected: the static user's bcrypt hash contains `$` sequences that expansion would mangle. The config keeps its path and carries four `@NAME@` placeholders (`@DEX_ISSUER@`, `@DEX_PORT@`, `@DEX_CLIENT_ID@`, `@DEX_REDIRECT_URI@`). The dex service mounts it read-only as a template and its command is `sh -c` running `sed` over the template into `/tmp/config.yaml`, then `exec dex serve /tmp/config.yaml`; compose passes the four values as environment variables (written `$$VAR` in the command so compose does not interpolate them). Omnigent's issuer, client id and redirect URI come from the same compose expressions, so both sides are derived from one variable each. Omnigent still listens on 8000 in its container; only the published port and the redirect URI move.

### Smoke

The smoke exports `OMNIGENT_PORT=18000`, `DEX_PORT=15556` and `OMNIGENT_OIDC_CLIENT_ID=omnigent-smoke` after sourcing `.env`, beside its existing isolation exports, so a developer's `.env` cannot hide the case and the quickstart ports stay free. It adds two assertions: dex discovery's `issuer` equals `http://dex.localhost:15556/dex`, and the `Location` of Omnigent's `/auth/login` carries the encoded overridden redirect URI and client id. The existing login-to-identity check then proves the end to end.

## Alternatives Considered

- **Dex `expandEnv`.** Rejected: mangles the bcrypt hash unless every `$` is escaped.
- **A rendered file written by the smoke or a host script.** Rejected: the quickstart (`docker compose up`) would still use the fixed file.
- **Keep dex on 5556 inside and publish `DEX_PORT:5556`.** Rejected: the issuer would name a port the Omnigent container cannot reach through the `dex.localhost` alias.

## Open Decisions

- none — the design follows from the issuer-equality rule recorded in spec 3; no open choice is left.

## Risks

- The dex image's entrypoint may not pass an `sh -c` command through; the smoke run is the proof, and the fallback is overriding `entrypoint` with `sh -c`.
- `sed` replacement breaks on a value containing `|`; ports, ids and URLs from `.env` do not, and the placeholders use `|` as the delimiter.
- Pulling images costs disk: the run aborts below 8 GB and removes only the images it pulled.
