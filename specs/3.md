## Problem

There is no runnable stack yet: the platform must come up with `docker compose up` on a developer machine before any server work. Ship the local compose profile — Omnigent pinned, a task router in front of Databricks Unity Gateway, Postgres and OIDC — with one test model endpoint.

Member S13 of holetz/forge epic 1 (Deliver the self-hosted AI-assisted development platform around Omnigent).

## Proposal

- `docker compose up` on a developer machine brings up Omnigent (server image pinned by version and digest), Postgres, a dev OIDC provider and a task router, all healthy, with no Databricks access and no paid model call.
- A person signs in to Omnigent through the OIDC provider and the server sees a named identity, not the single `local` user.
- Omnigent sends every LLM call to the router; the router picks the model by task (default Flash; escalation for security, architecture and repeated failure), strips the caller's credential, injects the upstream one from the environment, and forwards to an OpenAI-compatible upstream.
- The only model endpoint the stack ships is a local OpenAI-compatible stub; the Unity Gateway route exists as configuration only (host and token read from the environment, never committed).
- `scripts/smoke-local.sh` proves the above end to end and tears the stack down; `scripts/verify_repo.sh` validates the compose file and the router logic without Docker daemons or network.

## Out of Scope

- Server profile pieces — egress proxy, observability, MCP registry, 30-session sizing (S14, `after: S13`).
- Policy pack, budgets and cost views (S16, S21): the router records nothing and enforces no budget; the Opus escalation budget lives in Unity Gateway.
- A model-based task classifier (OpenJev): the router classifies by an explicit `X-Forge-Task` header only; classifier routing is a later swap behind the same interface.
- Any call to Databricks or any paid model, including from the smoke. The live check is a human step (see `## Handoff`).
- HTTPS / Caddy for the local profile and production IdP wiring (Entra ID): the dev provider is loopback HTTP only.
- Running agents inside the stack: Omnigent runs in external-runner mode; the runner is the developer's, started per Omnigent's prompt.

## Design

### Mapa de dependências

Greenfield for compose; the repository holds only the leak gate (`scripts/`, `.github/workflows/ci.yml`, `.gitignore`) and the H1 spike (`spikes/h1/`, which builds its own `forge-h1-opencode:local` image and shares nothing with the stack). The one coupling is `scripts/verify_repo.sh`, which CI runs unchanged; adding steps there reaches CI without touching `ci.yml`. Nothing orphans if `compose.yaml` changes. (2026-10-25)

### Stack

```
browser ──► omnigent :8000 ──► postgres
   │            │  OIDC discovery/token/jwks
   │            ▼
   └──────► dex.localhost:5556        (dev IdP, static user)
                │ LLM calls (OPENAI_BASE_URL)
                ▼
          router :4000 ──► default     ──► stub :8080  (or Unity Gateway, by env)
                      └──► escalation ──► stub :8080  (or Unity Gateway, by env)
```

The compose is derived from Omnigent's `deploy/docker/docker-compose.yaml` at v0.19.1 (same variable names), trimmed to what the profile needs. Omnigent is alpha: the version is bumped only by editing the tag and digest together (see `## Open Decisions`).

### Model routing

The router is one stdlib Python file. It exposes the OpenAI-compatible surface (`POST /v1/chat/completions`, `GET /v1/models`, `GET /healthz`), classifies each request by the `X-Forge-Task` header (`security`, `architecture`, `repeated-failure` → `escalation`; anything else or absent → `default`), rewrites the body's `model` to the route's model, drops the caller's `Authorization`, adds `Authorization: Bearer <route token>` from the environment, and streams the upstream response back unchanged (SSE included). Routes are read from the environment, one triple per route:

| Variable | Default (stub) | Live (Unity Gateway) |
|---|---|---|
| `FORGE_DEFAULT_BASE_URL` | `http://stub:8080/v1` | `https://<workspace>/ai-gateway/mlflow/v1` |
| `FORGE_DEFAULT_MODEL` | `system.ai.deepseek-v4-1-flash-1017` | same |
| `FORGE_DEFAULT_TOKEN` | `stub-token` | a workspace token, from the shell or `.env` |
| `FORGE_ESCALATION_BASE_URL` / `_MODEL` / `_TOKEN` | stub / `databricks-claude-opus-5-5` / `stub-token` | `https://<workspace>/serving-endpoints`, same model, same token class |

Model names are the epic's `## Design` §Model routing (Flash 1017 default through the Unity Gateway model service; Opus 5.5 escalation). Unity Gateway applies per-group permission, per-user limits and budget; the router only routes. The router refuses to start when a non-stub upstream is plain HTTP, so a token is never sent in clear.

**Credential rule (from S6 and S13).** S6 lost cases to `databricks auth token --force-refresh` failing with `keyring set timed out`. The stack therefore never shells out to a CLI or keyring: the token is a plain environment variable (PAT or OAuth M2M access token), supplied by the human at run time, and `.env` is git-ignored. `.env.example` is committed with placeholders only.

### Control points

The router is the single egress for model calls from the server: it is where S14's egress proxy and S21's cost recording attach. Identity is enforced at Omnigent via OIDC (the epic's Guardrails table, Identity row); the router adds nothing there and trusts only the compose network plus a loopback-only published port.

### OIDC dev provider

Dex (Apache-2.0, small, config-file driven, static users, no database) is the dev IdP. Omnigent requires the token issuer to equal `OMNIGENT_OIDC_ISSUER` exactly and a browser must also reach the issuer URL, so the issuer is `http://dex.localhost:5556/dex`: browsers resolve `*.localhost` to loopback with no `/etc/hosts` edit, and the compose gives the `dex` service the network alias `dex.localhost` so the Omnigent container resolves the same name. Discovery (no endpoint overrides) is used, since overrides would force loopback hosts the container cannot reach. The upstream compose has no `OMNIGENT_OIDC_REDIRECT_URI` passthrough and derives an `https://` URI from `OMNIGENT_DOMAIN`; this compose adds the passthrough (`http://localhost:8000/auth/callback`, the same code path Omnigent documents for raw-IP deploys), which also selects non-`__Host-` cookies for plain HTTP. Dex has one static user (`dev@example.com`, a documented dev-only password whose bcrypt hash is in `local/dex/config.yaml`) and one client whose secret is a random value minted into `.env`. Published ports bind to `127.0.0.1` only.

### Smoke without paid calls

`scripts/smoke-local.sh` does the whole proof with curl against the running stack: the router checks read the stub's `GET /_last` (model, whether the injected credential matched, whether the client's credential leaked); the OIDC check follows the redirect chain with a cookie jar through dex's password form and asserts the Omnigent session identity. It records free disk and the list of images present before `up`, and on exit (trap) runs `docker compose down -v` and removes only images that were absent before. It aborts before pulling when less than 8 GB would remain. A `.env` it generated itself is removed on exit; one that existed is left alone.

### Gate

`verify_repo.sh` gains: `docker compose --env-file .env.example config -q` (skipped with a printed line when `docker` is absent), and `python3 -m unittest discover` over `local/router` and `local/stub`. `ci.yml` is untouched; CI picks these up because it already runs `verify_repo.sh`.

## Alternatives Considered

- **LiteLLM as the router.** Rejected for the local profile: a ~1 GB image and a large surface for a routing rule that is a header lookup and a model rewrite; routing by task is not native, so a custom hook would be written anyway. It stays the candidate if S21 needs per-key spend inside the compose rather than in Unity Gateway.
- **Keycloak as the dev IdP.** Rejected: heavier image, slower boot and a database or realm import for one static user. Dex is enough because the adopter's real IdP is Entra ID, tested at the server profile.
- **Omnigent built-in accounts instead of OIDC.** Rejected: the epic's Identity control is corporate SSO via `OMNIGENT_OIDC_ISSUER`; accounts mode would leave the OIDC path unproved.
- **Run Omnigent from source with `pip` instead of the published image.** Rejected: no pin by digest, a slow build, and the image is what the server profile will run.

## Open Decisions

- **Router implementation is a stdlib script, not LiteLLM.** Decided by this spec on the evidence in `## Alternatives Considered`; it is reversible because Omnigent only sees `OPENAI_BASE_URL`. Revisited when S21 states whether per-key spend must live in the compose; settled by that spec's design.
- **Live check against Unity Gateway.** Not run here (no Databricks, no paid call). Settled by the human running the `## Handoff` step; until then the Unity route is unproven end to end.
- **Whether Omnigent's runner honours `OPENAI_BASE_URL` for the chosen harness.** Omnigent's Databricks guide sets it for the server-side agent; the external runner (OpenCode on Flash) takes its provider from its own config. Settled in the Handoff live check by pointing the runner at `http://localhost:4000/v1`; if it does not, the fix is runner config in S12, not the compose.
- **Omnigent upgrade policy** stays the epic's open decision; this spec only pins the current version.
- **Why now / not worth doing:** why-now is the epic's order (S13 unblocks S14, S16, S21 and S12); a reason to drop it would be Omnigent changing its configuration format before the pilot, which the pin and the thin compose contain.

## Risks

- **Omnigent alpha changes variables or image layout:** pin by digest; the smoke fails loudly on a bump that breaks boot.
- **GHCR or Docker Hub unreachable when the smoke runs:** the smoke fails at pull with the registry's error; nothing is partially left because teardown runs on exit.
- **A real token lands in the repository:** `.env` ignored, placeholders only in `.env.example`, `<workspace>` for hosts, the leak gate and gitleaks in CI; ACCEPTED — the dev-only dex password hash and the stub token are public by design and protect nothing.
- **`*.localhost` resolution differs by client:** browsers and curl resolve it; a client that does not (older libc resolvers) needs a hosts line. Mitigated by documenting it in `README.md`.
- **Disk pressure from image pulls on a small laptop:** the smoke checks free space first and removes what it pulled.
- **Stub drifts from the real API shape:** it implements only non-streaming and SSE chat completions; the Handoff live check is the proof against the real gateway.

## Handoff

Live check against Unity Gateway (human step, after merge; not run by this spec). Estimated cost: a few requests (under ten, each a short prompt) on `system.ai.deepseek-v4-1-flash-1017` at US$ 0.30 input / 1.20 output per 1M tokens, i.e. well under US$ 0.01.

1. Copy `.env.example` to `.env` (or let the smoke create one), then set `FORGE_DEFAULT_BASE_URL=https://<workspace>/ai-gateway/mlflow/v1` and `FORGE_DEFAULT_TOKEN` (a workspace token) in the shell or `.env`; leave the escalation route on the stub.
2. `docker compose up -d --wait`, then `curl -s http://localhost:4000/v1/chat/completions -H 'Content-Type: application/json' -d '{"model":"any","messages":[{"role":"user","content":"Reply with exactly: HELLO"}],"max_tokens":16}'`.
3. Expect HTTP 200 and an answer from `DeepSeek-V4.1-Flash-1017` (reasoning in `reasoning_content`); confirm one row in `system.ai_gateway.usage`.
4. Point a runner at the router (`OPENAI_BASE_URL=http://localhost:4000/v1`) and run one trivial Omnigent agent turn to settle the runner question in `## Open Decisions`.
