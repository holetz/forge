## Problem

Guardrails must live in a layer the agent cannot bypass by writing code, and Omnigent ships the mechanism but not the policies. Ship generic policies — approval before push and deploy, cost budgets, egress blocking, secret and PII detection on output — parameterised so an adopter supplies values and lists. Depends on the forge local profile (forge epic S13).

Formerly holetz/crucible#1.

Member S16 of holetz/forge epic 1 (Deliver the self-hosted AI-assisted development platform around Omnigent).

## Proposal

- A parameterised Omnigent policy pack exists in `policy/`: a Python module `forge_policies` registered through the server's `policy_modules`, with three policies of its own (approval before push and deploy, egress blocking, secret and PII detection on output) and the budget policies Omnigent already ships, all driven by one parameter file.
- `policy/params.default.json` holds the safe defaults; an adopter's `policy/params.json` (the slot `docs/overlay-contract.md` reserves) overrides it key by key, and a parameter file that does not validate is refused before anything starts.
- `scripts/render-policy-config.py` turns the merged parameters into the server config `policy/config.yaml` (JSON, which YAML accepts), and the repository gate fails when the committed file drifts from its defaults.
- `compose.yaml` mounts `policy/` read-only into the Omnigent service and points `OMNIGENT_CONFIG` and `PYTHONPATH` at it, so the pinned v0.19.1 server loads the pack on `docker compose up`.
- The overlay checker validates `policy/params.json` with the pack's own validator instead of checking only that it is an object.
- `scripts/smoke-local.sh` proves, against the pinned image and with the server's own loader, that each policy loads and returns the expected verdict (ASK on a push, DENY on a blocked host, DENY on a secret in a response, cost budget wired).
- `docs/policy-pack.md` documents every parameter, what each policy cannot do, and how an overlay supplies values.

## Out of Scope

- Redacting a secret in place on `response` or `tool_result` (an ALLOW carrying replacement `data`): the pinned docs promise the substitution only in general terms, so the pack blocks or asks and leaves redaction until a pin documents the phase. Ruled out for now, not forever.
- Changing the budget semantics: `cost_budget` and `user_daily_cost_budget` are a downgrade gate, not a hard stop. The hard block stays at the model gateway (Unity Gateway limits, S21).
- Porting an adopter's own agent hooks (compute guard, column-override guard) to policies: that is spike S17.
- Per-agent or per-session policy files: the pack is server-wide, the level an admin owns. Agent specs and sessions can still add their own.
- The egress proxy and the sandbox themselves (S14). The egress policy is a second layer in front of them, never a replacement.
- Any CI workflow or permission change: `.github/` stays untouched.
- Real hosts, tokens, emails or corporate vocabulary: every example value is synthetic.

## Design

**The mechanism is Omnigent's own, read from the pinned source (tag v0.19.1, commit fbad2c7, the version `compose.yaml` pins by digest).** A server admin lists `policy_modules` and a `policies:` mapping in the server config; each entry is `type: function`, `handler: <dotted path>` and `factory_params`. The server loads the file from `OMNIGENT_CONFIG` (default `/data/config.yaml`), imports the handler, calls it once with `factory_params` and gets an evaluator `evaluate(event) -> {"result": ALLOW|DENY|ASK, "reason": ...} | None`. Phases are `request`, `tool_call`, `tool_result`, `response`, `llm_request`, `llm_response`; a DENY short-circuits and ASK parks the action for user approval. Module `POLICY_REGISTRY` entries make a handler discoverable. Nothing here is invented; `docs/POLICIES.md` and `omnigent/policies/{function,registry,schema}.py` at that tag are the references.

**One module, three own policies, budgets delegated.** `forge_policies` is stdlib-only and imports nothing from `omnigent`, so its unit tests run without the server. Budgets are not reimplemented: the rendered config names `omnigent.policies.builtins.cost.cost_budget`, `...cost.user_daily_cost_budget` and `...safety.max_tool_calls_per_session` directly (wrapping `max_tool_calls_per_session` would lose the runtime state-key authority the engine grants only to the resolved builtin). A budget parameter set to `null` drops that policy from the rendering.

**Parameters, merged and validated in one place.** `params.py` merges `policy/params.default.json` with an optional overlay file, key by key at the first level (a list or an object in the overlay replaces the default value whole), refuses unknown keys, wrong types, negative or non-increasing budgets (soft thresholds must be below the hard limit, as Omnigent requires), and renders the config. `render-policy-config.py` is a thin command over it; `overlay-check.py` imports the same validator, following the pattern S15 set (the contract is enforced by calling the code).

| Group | Keys | Default |
|---|---|---|
| `approval` | `commands` (word sequences), `tools` (tool-name globs), `action` (`ASK` or `DENY`) | ASK on `git push`, registry and image pushes, `terraform apply`, `kubectl apply`, `helm install/upgrade`, `databricks bundle deploy`, `gh pr merge`, `gh release create`, package publish; tools `mcp__*__push*`, `mcp__*__deploy*` |
| `budget` | `session_max_usd`, `session_ask_usd`, `daily_max_usd`, `daily_ask_usd`, `expensive_models`, `max_tool_calls` | session 10 (ask at 5), daily 25 (ask at 10 and 20), 200 tool calls; `expensive_models` omitted so the builtin default applies |
| `egress` | `allow_hosts`, `deny_hosts`, `network_tools`, `shell_network_commands`, `action_unparsed` | allow loopback only; deny nothing extra; unparsable network command is ASK |
| `output` | `detect` (category names), `extra_patterns`, `action`, `phases` | secrets and CPF, CNPJ, card (Luhn), SSN; DENY; phases `response` and `tool_result`; email and phone are opt-in categories |

**Approval reads the command, not a first token.** For the shell tools (the same family Omnigent lists as `SHELL_TOOLS`: `sys_os_shell`, `Bash`, `bash`, `Shell`, `terminal`, `developer__shell`, `shell`) the command is split into segments on `;`, `&`, `|` and newlines, tokenized with `shlex` (whitespace split when that fails), and a configured sequence matches when its first word is a token's basename and each following word is the next non-option token (known value-taking options such as `git -C <dir>` are skipped). Wrappers need no special case because the head is searched, not assumed first; the cost is a false ASK on `echo git push`, which is accepted. It deliberately does not import Omnigent's private `_shell` module, which may change between pins. A segment that cannot be tokenized and contains a configured first word is ASK, never ALLOW.

**Egress extracts hosts, fails toward ASK.** For `network_tools` it reads `url`, `uri` and `href` arguments; for shell tools it reads URL hosts, `user@host:` forms and the host argument of the configured network commands (`curl`, `wget`, `ssh`, `scp`, `rsync`, `nc`, `telnet`, `ftp`). A host matches an entry exactly or as a subdomain. `deny_hosts` always wins; a non-empty `allow_hosts` denies the rest; a network command with no extractable host takes `action_unparsed`. Reasons name the host, never the full command.

**Output scanning never echoes a hit.** `output.py` scans `response` and `tool_result` text (strings, and the string leaves of dicts and lists) with built-in patterns for private-key headers, `dapi` tokens, cloud and VCS access-key shapes, bearer JWTs, CPF and CNPJ (check digits verified), card numbers (Luhn) and SSN. The reason carries the category and a count only. Every pattern that would itself match the repository's leak scan (a private-key header, for instance) is built from fragments in source, and tests assemble their fake secrets at run time, so no tracked file trips `leak-generic.sh` or gitleaks.

**Wiring.** `compose.yaml` adds `./policy:/policy:ro`, `OMNIGENT_CONFIG: /policy/config.yaml` and `PYTHONPATH: /policy` to the `omnigent` service (the image sets no `PYTHONPATH` of its own, checked at execution). `policy/config.yaml` carries only `policy_modules` and `policies`; secrets never belong in it. An overlay renders its own config from its `policy/params.json` and mounts it over `/policy/config.yaml` from its compose override. Policies run in the server process, so the mount is read-only and the module is code an admin controls, not an agent.

**The proof uses the real loader.** Inside the running pinned container the smoke calls `omnigent.spec.parse_default_policies`, `omnigent.policies.registry.load_registry(['forge_policies'])` and `resolve_function_policy`, then evaluates synthetic events. No OIDC session, no model call, no Databricks.

**Binding contracts:** `.github/workflows/` untouched; no real host, token, email or corporate term; hooks stay on; `docs/overlay-contract.md` keeps "an overlay never holds a credential".

## Alternatives Considered

- **A sidecar policy service (OPA, Presidio, gitleaks) behind a thin policy.** Rejected for this spec: it adds containers, images and a network hop to a local profile that must stay small, and the epic lists those tools only as an option. Pattern checks in-process cover the generic pack; a heavier detector can be added later behind the same `output` parameters.
- **Wrapping Omnigent's builtin shell parser and `github_policy` for push approval.** Rejected: `_shell` is a private module that may move between alpha pins, and `github_policy` is a repo allowlist rather than a deploy gate. The pack's own segment matcher is small, tested, and fails toward ASK.
- **Per-agent policies in agent specs instead of server config.** Rejected: guardrails must sit where an agent cannot rewrite them; the server level is evaluated last and cannot be removed by an agent or a session.
- **Reading the parameter file at policy build time instead of rendering a config.** Rejected: the rendered config shows the real values an admin gets, is checked for drift in the gate, and keeps the policies pure functions of their `factory_params`.

## Open Decisions

- **Redaction instead of block on output.** Decided when a later pin documents replacement `data` on the `response` and `tool_result` phases, proven by the same real-loader smoke; until then the pack blocks or asks.
- **Hard budget stop.** `cost_budget` only gates expensive models over the cap. Whether a true stop is needed is decided by S21 (cost per person, team and session), which owns the gateway limits.
- **Default `allow_hosts`.** Loopback only is the safe default and makes a fresh stack unable to reach an external git host; the adopter's overlay supplies theirs. Revisit after the H3 pilot shows real friction.

## Risks

- **Omnigent is alpha and the policy API may change.** Mitigation: the compose pins the image by digest, the smoke runs the real loader against exactly that pin, and a bump of the pin must re-run it; the module imports nothing from Omnigent.
- **Pattern gates are bypassable** (encoded commands, a script file, split tokens, a secret in an unusual shape). ACCEPTED — these policies are a visible, auditable layer; the hard layers are the sandbox, the egress proxy and the model gateway, and the docs say so.
- **False ASK and false DENY** (`echo git push`, a number that passes Luhn). Mitigation: check digits for CPF, CNPJ and cards; categories and commands are parameters; ACCEPTED for the shell substring case because failing open is the worse error.
- **A bad parameter file silently weakening a guardrail.** Mitigation: unknown keys and wrong types are refused by the validator, in the renderer, in `overlay-check.py` and in the gate.
- **A server that cannot import the module.** The registry loader logs and skips a module that fails to import, so a typo in the mount would leave no pack. Mitigation: the smoke asserts the three handlers resolve inside the running container, and the docs name the check.
- **The module is trusted code in the server process.** Mitigation: read-only mount, repository review, no network access in the module.
- **Leak scan tripping on pattern sources.** Mitigation: patterns assembled from fragments, fake secrets built at run time, gate step `leak-generic.sh` runs over the new files.
