## Problem

A nossa maquina ainda roda o Omnigent pelo wheel publico, com configuracao ad hoc (`uv tool`, `omni opencode`, proxy Databricks, `~/.config/opencode/opencode.jsonc`), e nao pelo stack do Forge com um overlay privado da UNicred. O modelo DeepSeek V4.1 Flash 1017 e a janela de 1M estao resolvidos por um override global no host, nao por configuracao versionada do overlay.

## Proposal

Criar o overlay privado da UNicred fora do repo do Forge, a partir de `overlay/example/`, e subir o server profile na nossa maquina:

- overlay: `overlay.json`, `overlay.env`, `compose.overlay.yaml`, `upstreams.json`, `registry.json`, `policy/params.json`, `agents/*.json`;
- identidade: OIDC da UNicred no lugar do dex, com issuer/client/secret fora do repo;
- modelo: DeepSeek V4.1 Flash 1017 via Databricks AI Gateway, roteado pelo router/egress do Forge;
- contexto: `AP_CONTEXT_WINDOW_OVERRIDE=1000000` no processo do runner/host e, se necessario, no servidor; `limit.context=1000000` no OpenCode do runner;
- validacao: login OIDC, uma chamada real ao DeepSeek, anel de contexto em 1M (nao 128k), allowlist de modelos, politica de budget e smoke do Forge;
- segredos: so no shell/secret store; o overlay nao guarda valor de credencial; rodar `scripts/overlay-check.py` e o leak gate.

## Open Decisions

- Qual maquina e a "nossa maquina" e se o primeiro alvo e o local profile ou o server profile.
- Onde fica o repo privado do overlay (nome, org, visibilidade).
- Se o 1M fica como override global no host ou vira patch targeted no forwarder/catalogo do Omnigent.
- Se o host nativo (`omni opencode`) continua em paralelo ao stack Docker durante a migracao.
