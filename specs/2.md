## Problem

The business case rests on DeepSeek V4.1 Flash running the quenching commands close to a Claude baseline; if it does not, cost returns to frontier-model levels. Run the quenching eval suites (quenching S2) with Flash on OpenCode (quenching S3) and with the baseline on the same cases, fix the quality threshold, and decide the light-tier model (Flash or Haiku 5.5) and whether routing turns hybrid.

Member S6 of holetz/forge epic 1 (Deliver the self-hosted AI-assisted development platform around Omnigent).

## Proposal

- A reproducible H1 harness lives in `spikes/h1/`: a disposable OpenCode container image, harness profiles for quenching's `scripts/run_evals.py` (S2) and a driver that runs the same cases against every model arm.
- The three suites H1 names (specs `specs/create`, git `git/commit`, knowledge `knowledge/define`, 9 cases, 30 assertions at quenching `155dd4a77`) are run with the OpenCode port (S3) on every reachable arm: baseline `databricks-claude-opus-5-5`, `databricks-claude-sonnet-5-5`, light tier `databricks-claude-haiku-5-5`, subject `databricks-deepseek-v4-1-flash`, and the declared open fallback `databricks-glm-5-3-flash` (epic 1 §Model routing).
- `spikes/h1/REPORT.md` records, per suite and per arm, the case approval rate, the assertion pass rate, tokens and US$; the quality threshold H1 fixes; the light-tier verdict (Flash or Haiku 5.5); and whether routing turns hybrid.
- Every endpoint fact observed on profile `ia` is recorded, including that no `databricks-deepseek-v4-1-flash-1017` endpoint is listed.

## Out of Scope

- Changing quenching itself (runner, suites, OpenCode port): the spike consumes S2 and S3 at a pinned commit from a fresh clone under `/tmp`; a runner or suite defect found here is a discovery for holetz/quenching, not a fix in this branch.
- The `components/hook:new` and `components/agent:new` suites: H1's signal names specs, git and knowledge only.
- Wiring the routing into the compose router or Unity Gateway (S13/S21): this spike decides the routing, it does not deploy it.
- Pi as an alternative harness: only if OpenCode itself fails here, which is a separate spike.
- OpenJev classification and LLM-as-judge in the gateway: the grader is fixed per run, not the gateway policy.

## Design

### Mapa de dependências (2026-10-24)

| File | Role here | What breaks if it changes |
| --- | --- | --- |
| quenching `scripts/run_evals.py` | fixture provisioning, snapshot, grading, `benchmark.json` | the profile contract (`argv`, `{arm}`, `{extra}`, `output`) this spike's profiles rely on |
| quenching `scripts/eval_harnesses.json` | the shipped `opencode` profile (`opencode run --model {model} --format json`) | nothing here: this spike passes its own file with `--harnesses` |
| quenching `plugins/quenching/assets/evals/{specs/create,git/commit,knowledge/define}/` | the cases, `setup.sh` (bare `origin.git` next to the workspace), `inspect.sh` | case ids and assertion counts in the report |
| quenching `plugins/quenching-opencode/` | the S3 port: 61 commands as `/quenching-<front>-<verb>`, payload under `~/.config/opencode/quenching` | the per-suite `--command` names |
| `~/.databrickscfg` profile `ia` | host and `databricks-cli` OAuth | token minting per case |

### Decisions

- **One harness, model as the only variable.** Every arm, baseline included, runs on OpenCode with the same port, the same cases, the same `--max-turns` and the same grader; only `--model` changes. Comparing Flash-on-OpenCode with Opus-on-Claude-Code would confound harness and model.
- **The command is invoked, not guessed.** OpenCode loads commands, not auto-triggered skills, so each suite gets its own profile whose `with` arm is `--command quenching-<front>-<verb>` and the case prompt is the command's `$ARGUMENTS`: `specs/create` → `quenching-specs-create`, `git/commit` → `quenching-git-commit`, `knowledge/define` → `quenching-knowledge-define`. Trigger accuracy is therefore not measured; the `Not for:` boundary cases still are, since the body must decline.
- **Every agent runs in a disposable container.** The profile's argv is `bash spikes/h1/agent.sh`, which runs `docker run --rm` as the host uid with exactly one bind mount: the case's fixture directory (the runner's temporary `eval-*` directory, holding `workspace/` and the `origin.git` that `setup.sh` places beside it). The image carries OpenCode (pinned `opencode-ai` 1.19.4), python3, git and the quenching-opencode payload copied at build time from the clone. The permission bypass `--auto` exists only as `--extra-arg` inside the container's argv; nothing on the host runs with a bypass, consistent with quenching 2047's runner default.
- **The credential stays out of argv and out of the agent's environment.** The driver mints a fresh OAuth token per case (`databricks auth token -p ia`) and exports it; `agent.sh` passes it by name (`-e DATABRICKS_TOKEN`); the entrypoint writes it to a file inside the container's own filesystem, unsets the variable and execs OpenCode, whose provider reads `{file:...}`. Results are scanned for token shapes before they are committed.
- **Provider.** OpenCode's `@ai-sdk/openai-compatible` provider at `https://<host>/serving-endpoints`, one model entry per endpoint (verified: `databricks-claude-haiku-5-5` and `databricks-glm-5-3-flash` answer tool calls on that API).
- **Grader fixed across arms**: Opus 5.5 on the same container, no command loaded, default text output so `parse_grades` reads a plain JSON array. Tokens of the agent arm come from OpenCode's `--format json` step events, summarised by the entrypoint onto stderr as one `H1-USAGE {json}` line, so the graded stdout stays plain text.
- **US$ from the epic's price table** (`spikes/h1/prices.json`, US$ per 1M tokens, US$ 0.07 per DBU), applied per token class the events report (input, output, cache read, cache write).
- **Threshold rule (assumption, named):** an arm is *close to the baseline* on a suite when its case approval rate is at least 80% of the baseline's and its assertion pass rate is within 10 points; an arm passes H1 when it is close on all three suites. Hybrid routing is *yes* when the default-tier candidate fails any suite.
- **Endpoint facts at develop time (2026-10-24, profile `ia`):** `databricks-deepseek-v4-1-flash` is listed `READY` but every call returns `BAD_REQUEST: This endpoint databricks-deepseek-v4-1-flash is deprecated`; `databricks-deepseek-v4-flash-0731` answers the same; no `databricks-deepseek-v4-1-flash-1017` endpoint is listed. The Flash arm is still attempted in execution and recorded as it answers.

## Alternatives Considered

- **Baseline on Claude Code, Flash on OpenCode** — lost: confounds harness with model, and the epic routes Claude Code only to escalated Opus sessions.
- **Run the agents on the host with `--auto`** — lost: an unattended permission bypass on the developer's machine, refused by quenching 2047's runner default and by this run's instructions.
- **Patch `run_evals.py` to call docker itself** — lost: changes S2 from a consumer spike; the profile file plus a host wrapper reaches the same isolation without touching quenching.
- **Substitute GLM 5.3 Flash for DeepSeek Flash as the H1 subject** — not taken alone: changing the subject is the owner's decision; GLM runs as an additional arm, labelled fallback.

## Risks

- The subject endpoint is unreachable (deprecated) — mitigation: the arm is attempted and recorded; the baseline, light tier and fallback arms still produce the comparison, and the verdict for Flash stays `not measured`.
- Nine cases is a small sample; one case flips a suite's approval by 33 points — ACCEPTED — the spike reports both case approval and assertion pass rate and names the sample size.
- Grader self-preference: Opus grades its own arm — ACCEPTED — the grader is fixed for every arm and evidence must be verbatim (`verify_grades`), which bounds invention.
- The agent reads the token file inside the container — mitigation: the token is short-lived, minted per case, never in argv, and results are scanned before commit.
- The OAuth token expires mid-case on a slow arm — mitigation: one token per case, and a failed case shows as `errors` rather than a silent fail.
- Arg length: the grader prompt is one argv token of up to ~120k characters — ACCEPTED — under Linux's 128 KiB per-argument limit for ASCII material; an `E2BIG` shows as a grader error.
