## Problem

The hosted Omnigent must hand the quenching workflow to every user without anyone installing a plugin, and update it centrally. Verified on 2026-10-27 against Omnigent 0.19.1 on an isolated server:

- `OMNIGENT_BUILTIN_AGENT_DIRS` registers a bundle as a built-in agent for every user and replaces it in place when its content hash changes (`server/app.py`).
- Bundled skills reach an OpenCode session through Omnigent's `load_skill`.
- Bundle `sub_agents` run with their own policy enforced.
- A bundle loses executable bits on the way to the runner host, so no payload travels in it.

## Proposal

`deploy.sh` assembles and registers the quenching operator agent (`plugins/omnigent/quenching/` of a pinned quenching tag, see holetz/quenching#2115).

- **Pin:** the overlay supplies `quenching: {tag, sha256}`. `deploy.sh` fetches that tag, checks the sha256 of the bundle tree and refuses on mismatch.
- **Skills slot:** a new slot in the overlay contract (S15). The overlay's `skills/` merge into the bundle's `skills/`. A name that collides with a quenching skill is refused unless the overlay lists it under an explicit `replace:`. An optional `instructions.append.md` is appended to `instructions.md`. The overlay's harness and model defaults are written into `config.yaml`.
- **Registration:** the assembled bundle is mounted read-only into the `omnigent` service, and `OMNIGENT_BUILTIN_AGENT_DIRS` points at it. `upgrade` re-assembles from the new pin; `rollback` restores the previous pin.
- **Host prerequisites:** the session host carries `uv`, `git` and an OpenCode version the pinned Omnigent accepts, so the bundle's `uvx` launch of `quenching-mcp` works. The egress allowlist admits the git host the tag is fetched from.
- **Upgrade flow:** a quenching release produces a PR on the overlay that bumps the pin; a human merges it; `deploy.sh upgrade` applies it. Tracking quenching's `main` is not supported.

## Open Decisions

- **Decided by the owner on 2026-10-27:** one operator agent, no agent per command, the overlay skills slot with the collision rule, the pin with human-gated upgrades.
- **Still open:** the private overlay repository's location; whether the first deploy targets the conductor's machine (local profile) or `<server-host>` (server profile).
- **To measure here:** whether a session open during an upgrade keeps the old bundle or switches to the new one.
