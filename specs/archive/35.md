## Problem

The 2026-10-25 review of PRs #28–#34 found nine defects. The conductor reproduced the first one: `_shell_hit('bash -c "git push origin main"', [('git','push')])` returns `None`, and so does `(git push)`.

1. **Approval and egress bypass via a wrapper shell (medium).** `policy/forge_policies/approval.py:23,31` and `egress.py:117,120` tokenize with shlex, so a `bash -c`/`sh -c` payload, `(…)` subshells and `$(…)` are invisible. Fix: recurse into `-c` payloads of known shells and into subshell or command-substitution tokens. When a command cannot be parsed, apply the policy's blind handling, ask or deny, rather than allow. Test `bash -c`, `sh -c`, `env X=1 bash -c`, `(git push)` and `$(git push)`.
2. **Egress decoy host (medium).** `egress.py:126-133` stops at the first host-like argument, so `curl localhost evil.example.org` passes. Option values are not skipped either, as in `curl -o localhost evil.example.org`. Fix: judge every host-like argument, and deny if any one is outside the allowlist.
3. **Failed upgrade loses the last good release (medium).** `scripts/deploy.sh:298,322-325` moves `current` and `previous` before the new release is proven, and records a failed release as `previous`. This contradicts `docs/deployment.md:37`. Fix: move links only after the health check passes; on failure, bring the previous release back up and leave the links unchanged. Alternatively, keep a `last-good` pointer that only a healthy release updates. Test both failure paths.
4. **`--root` accepts `/`, `.` and absolute paths (low-medium).** At `deploy.sh:59,304,428`, `chmod 700` could hit a shared directory or the home directory. Fix: accept only a relative path below the home, with at least one segment that is not `.` and no leading `/`. Test it.
5. **Cost MCP rebuilds the DB on every request (low).** At `server/cost/cost_mcp.py:231`, `setdefault` evaluates its argument eagerly. Fix: load lazily, once.
6. **`budget_status` ignores `period` (low).** At `server/cost/cost.py:106`, with no `since`/`until` the window defaults to the budget's period, for example the current month. Test it.
7. **Overlay leak scan gaps (low).** At `scripts/leak-overlay.sh:56`, an IPv6 literal host passes and URL userinfo credentials are discarded unchecked. Fix: parse bracketed IPv6, and refuse any `user:password@` userinfo in overlay values. The `overlay-check.py` contract (`docs/overlay-contract.md:40`) says an overlay never holds a credential value.
8. **Example overlay replaces default lists (low).** At `overlay/example/policy/params.json:2,4` with `params.py:52`, the example drops 12 approval commands and the loopback hosts. Fix: merge with explicit add/remove semantics, such as `commands_add` and `commands_remove`, or make the example extend the defaults. Document which one applies. Prefer whichever keeps safe defaults unless they are removed explicitly.
9. **Docs describe `bash -s` (low).** `docs/deployment.md:7` says `bash -s`, but `deploy.sh:169` copies itself to a temp file. Fix the doc.

Done when each item has a test, or for item 9 a doc fix; the gate and CI are green; and no CI workflow or grant changes. Then `scripts/deploy.sh` runs once more on `<server-host>`: deploy, a forced failing upgrade, recovery, and down. Pass the address only at run time, and never touch the host's other stacks.

Member of holetz/forge epic 1 (follow-up of S15, S16, S21, S41).

## Proposal

- A shell command wrapped in `bash -c`, `sh -c` (also `zsh`, `dash`, `ksh`, with `env X=1` or other prefixes), a `(…)` subshell or a `$(…)` / backtick substitution is judged by the approval and egress policies exactly as its inner command would be; a payload that cannot be parsed takes the policy's blind handling (`ASK`/`DENY`), never an allow.
- The egress guard judges every host-like argument of a network command, including option values (`curl -o localhost evil.example.org`), and denies when any one is outside the allowlist.
- `deploy.sh upgrade` leaves `current` and `previous` untouched until the new release is proven healthy; on a failed upgrade the previous release is brought back up and the links are unchanged, which matches `docs/deployment.md`.
- `--root` / `FORGE_DEPLOY_ROOT` accepts only a relative path below the home with at least one real segment; `/`, `.`, `./.` and absolute paths are refused.
- The cost MCP loads its database lazily, once per server process, not on every request.
- `budget_status` without `since`/`until` reports the current period of the budgets file (`month`), not all time.
- `leak-overlay.sh` checks bracketed IPv6 literal hosts and refuses any `user:password@` userinfo in overlay values.
- Policy parameter overrides gain explicit list edits (`<list>_add`, `<list>_remove`) on top of whole replacement; the example overlay uses them and keeps the 15 default approval commands and the loopback hosts.
- `docs/deployment.md` describes what the script does (copies itself to a temp file on the host), not `bash -s`.
- Item 3 is proven on a real host: deploy, a deliberately failing upgrade, recovery to the last good release, `down --volumes`, with the fingerprint of containers outside `forge` identical before and after.

## Out of Scope

- Making the pattern checks sound: `policy-pack.md` already states they are bypassable (encoded commands, script files, split tokens). This spec closes the named wrapper, subshell and decoy-host holes only; a full shell parser was ruled out as disproportionate for a second-layer guard.
- Any CI workflow, permission or grant change (`.github/**` stays as is).
- Changing the model upstreams: they stay on the stub; the Unity Gateway switch stays manual.
- Reverting database changes on rollback (already documented as not done).
- A new `last-good` pointer file: links moving only after health is enough (see Design).

## Design

Rules, with the alternatives weighed:

- **One expansion, two guards.** A new stdlib helper `shellwords.expand(command)` returns `(segments, ok)`: every segment of the line as a token list, with the payload of `bash|sh|zsh|dash|ksh -c <payload>` (after `env`/`VAR=x` prefixes and options) recursed into, `(…)` subshells and `$(…)`/backtick substitutions lifted out as their own segments, to a bounded depth. `ok` is false when any payload cannot be parsed or the depth bound is hit; the caller then applies its blind handling (approval: a hit on the first word of any sequence found in the raw text, as today; egress: `action_unparsed`). Chosen over regex patches per guard because the two guards already drifted (same `_SPLIT`, same hole); a shared helper fixes both once. Both guards import it as `forge_policies.shellwords`, loaded by the package, so no `policy_modules` change.
- **Egress judges all host-like arguments.** Remove the `break`; collect every host-like token after the network head, skipping only `-x` option tokens that carry no host. Values of options are therefore judged too: a false positive (an option value that looks like a host) is accepted over failing open, consistent with `policy-pack.md`. Deny wins.
- **Deploy: links move after health.** `cmd_health` takes an optional release dir (default `current`). `cmd_upgrade` runs `up_release` and the health check on the new dir first; only on success `set_links` runs. On failure of either step it brings the old release back up (`up_release "$ROOT_ABS/$old"`) and exits non-zero with the links unchanged, so `previous` never holds a failed release. `cmd_deploy` (first install) keeps linking first because no good release exists to lose. Testable by sourcing the script and stubbing `up_release`/`cmd_health`/`dc_in`.
- **Root shape.** `valid_token root` accepts `^[A-Za-z0-9._/-]+$` that does not start with `/`, has no `..` segment, and has at least one segment that is neither empty nor `.`. `run_on_host` drops the absolute branch: `ROOT_ABS="$HOME/$ROOT"`. The script still `chmod 700`s only that directory.
- **Cost MCP.** Replace `state.setdefault("db", cost.load(reader))` with `if "db" not in state: state["db"] = cost.load(reader)` in the handler's closure; test with a counting reader that two requests read once.
- **Budget period.** `budget_status(db, budgets, since=None, until=None, today=None)`: with neither bound and `budgets["period"] == "month"`, the window is the first to the last day of `today`'s month (`today` defaults to the current UTC date, injectable). `day` and `year` are handled the same way; an unknown period keeps all time. The fixtures use fixed dates, so existing assertions pass an explicit window or an injected `today`.
- **Overlay scan.** The host regex accepts `[...]` bracketed IPv6; `host_ok` accepts only `::1` among IPv6 literals. A new check reports `credential-userinfo` for any `scheme://user:pass@` (a `:` before the `@`) at file:line, never echoing it. The existing test "host behind userinfo and a port" is rewritten to expect the userinfo rule.
- **Params: `_add` / `_remove`.** `merge()` honours `<key>_add` and `<key>_remove` for any list key of `_STR_LISTS`: the result is `(replacement-or-default) + add − remove`, and the suffixed keys never reach the merged dict, so the schema is unchanged. A plain `<key>` still replaces whole. The example overlay becomes `commands_add` and `allow_hosts_add`, so defaults stay unless removed explicitly. `overlay-check.py` needs no edit: it merges through the pack, and a suffixed key on a non-list key stays an unknown key.
- **Docs.** `deployment.md` describes the temp-file copy and that a failed upgrade leaves the links unchanged; `policy-pack.md` documents `_add`/`_remove` and wrapper handling; `overlay-contract.md` states IPv6 and userinfo are refused; `cost.md` states the default period.
- **Remote proof protocol.** The run uses `FORGE_HOST` from the environment of the one command only, `--root` a dedicated relative directory, and the shipped `deploy.sh` commands. `others` before and after bracket it. Nothing outside the `forge` compose project is stopped, pruned or touched.

Binding contracts: Omnigent policy loader imports the `forge_policies` package (stdlib only); `docs/overlay-contract.md` (an overlay never holds a credential); public repo (no real host, user or token; gitleaks hooks stay on, no `--no-verify`).

## Alternatives Considered

- Full shell AST parser (e.g. a bundled bashlex): rejected, adds a dependency to a stdlib-only pack and still cannot see scripts or encodings.
- Blanket `ASK` for any command containing `-c`, `(`, or `$(`: rejected, too many false positives on ordinary work.
- A `last-good` pointer file for deploy: rejected for now, because moving `current`/`previous` only after health already keeps `previous` honest and adds no second source of truth.
- Replace-only semantics with a doc warning for the example overlay: rejected, it is the footgun the review found.

## Open Decisions

- How the remote failing upgrade is provoked: first a ref that does not resolve (fails before any change), then, if a health failure is wanted, a throwaway public-safe branch whose compose cannot become healthy. Decided at task 5.2 by what the host run shows; whichever paths are exercised remotely are named in the report, and both paths are covered locally by task 2.1.

## Risks

- A recursive expansion could loop or blow up on adversarial input: bounded depth (3) and a segment cap; hitting a bound is blind handling, never allow.
- Judging every host-like argument may deny a harmless command whose option value looks like a host: ACCEPTED, safe side, consistent with the documented policy.
- A failed-upgrade recovery that itself fails leaves no stack up: the script exits non-zero naming the manual `rollback`/`deploy` step.
- The remote proof touches a real host: confined to the `forge` project and a dedicated relative root; `others` fingerprints before and after prove nothing outside moved; if they differ the run stops and returns `needs-human`.
- The leak hook may flag an IPv6 or userinfo test literal: test literals are assembled at run time, as `test-leak-overlay.sh` already does.
- `budget_status` default window changes the MCP output for callers who relied on all time: documented in `docs/cost.md`; an explicit `since`/`until` still wins.
